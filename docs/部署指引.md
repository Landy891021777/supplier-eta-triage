# 部署指引

把專案推上 GitHub，並部署成可公開點擊的 Streamlit 網址。

**預估時間：GitHub 約 10 分鐘，雲端部署約 10 分鐘。**

---

## 一、推送前確認沒有機密進版控

```bash
git status --short
git ls-files | grep -E "^\.env$|secrets\.toml|面試防彈說法" || echo "OK"
```

**輸出必須是 `OK`。** API 金鑰一旦推上 GitHub，就必須當作已外洩並立刻撤銷重發。

`.gitignore` 已排除：`.env`、`.streamlit/secrets.toml`、`.cache/`、`data/` 下的產物、個人筆記。

---

## 二、推上 GitHub

### 設定 git 身分（只需一次）

```bash
git config --global user.name "你的名字"
git config --global user.email "你的 Email"
```

### 建立空的 repository

到 <https://github.com/new>：

- Repository name：`supplier-eta-triage`
- **Public 或 Private 都可以**：面試官要看程式碼就要 Public；Private 也能部署（見第三節）
- **不要**勾選 README、.gitignore、license（專案已有這些檔案）

### 推送

```bash
git remote add origin https://github.com/<你的帳號>/supplier-eta-triage.git
git branch -M main
git push -u origin main
```

第一次推送會要求驗證，會跳出瀏覽器登入視窗；若沒有，改用 Personal Access Token
（GitHub → Settings → Developer settings → Fine-grained tokens，權限 `Contents: Read and write`），
在「密碼」欄位貼上 token。

推完打開 repo 頁面確認：README 正常顯示、**`.env` 不在檔案列表中**。

---

## 三、部署到 Streamlit Community Cloud

1. 到 <https://share.streamlit.io>，用 GitHub 帳號登入
   - **Private repo**：第一次登入時要授權 Streamlit 讀取私人 repo
     （GitHub 授權畫面要勾選私人 repo 的存取權）；否則選 repo 時會找不到
2. **Create app** → 選 `supplier-eta-triage` repo
3. 設定：
   - Branch：`main`（**一個 App 綁一個分支**：要展示別的分支，得另外部署一個 App，
     會拿到另一個網址；分支合併到 `main` 後，綁 `main` 的 App 會自動更新）
   - Main file path：`app.py`
   - **Advanced settings → Python version：3.12**
4. **Advanced settings → Secrets** 貼上（金鑰換成你自己的）：

```toml
LLM_PROVIDER = "gemini"
GEMINI_API_KEY = "你的金鑰"
GEMINI_MODEL = "gemini-3.5-flash-lite"
GEMINI_EMBED_MODEL = "gemini-embedding-001"
LLM_CALLS_PER_SESSION = "20"
```

5. **Deploy**，等候 3 到 5 分鐘

### 第一次啟動會發生什麼

工具偵測到沒有資料時會依序自動產生：合成資料 → 模擬 ERP 資料庫 → 歷史單據。
約需 10 到 20 秒，不需要任何手動操作。

解析結果、知識卡向量與範例問答都由 `demo_cache/` 提供，**冷啟動不會呼叫 API**。

---

## 四、公開展示的保護設計

**公開網址代表任何人都能用你的 API 金鑰**（即使 repo 是 Private，App 網址本身仍是公開的）。
專案內建兩層保護：

| 機制 | 作用 |
|---|---|
| **種子快取** `demo_cache/` | 首頁解析、語意索引、6 個範例問答皆預先算好，訪客點範例不消耗配額 |
| **工作階段額度** `LLM_CALLS_PER_SESSION` | 每位訪客最多觸發 20 次未快取的 LLM 呼叫，用完後改為列出原始資料或使用模板，工具照常可用 |

**一定要另外做的事**：到 Google AI Studio 為這把金鑰設定用量上限，或為展示專用另建一把金鑰。
內建的額度只擋單一工作階段，擋不住很多人同時開。

### 何時需要重新匯出種子快取

修改了 prompt、資料產生器、知識庫卡片內容或範例問題後，快取鍵會改變，種子會失效。
在本機（`.env` 需有金鑰）重新執行後提交：

```bash
py -X utf8 scripts/export_demo_cache.py
git add demo_cache && git commit -m "chore: 更新部署用種子快取"
git push
```

## 五、部署後檢查清單

- [ ] 側邊欄顯示「LLM 已連線」
- [ ] 左側選單分「企劃工作區」與「專案說明」兩區
- [ ] 「今日行動清單」首頁數字：收到信件 52、今天要處理 P1 21
      （開 LLM、命中種子快取時的數字；關 LLM 的規則層模式是 P1 15）
- [ ] 行動清單有「批次」欄；PO-2026-04188 的批次顯示「1（供應商提議拆 2 批之 2）」
- [ ] 「⬇️ 匯出明日追料清單（Excel）」能下載、打得開
- [ ] 「物料智能檢索」頁的檢索模式顯示「語意檢索 ＋ 識別碼精確比對」
- [ ] 點任一範例問題，回答幾乎立即出現（代表命中種子快取）
- [ ] 「🧪 方法驗證」頁的回測、解析、檢索三份報告都能顯示
- [ ] 「🏭 供應商績效」頁有歷史表現與月度績效
- [ ] 「🛠 收貨處理天數」頁可以送出一筆調整（展示環境的調整在 App 休眠或重新部署後會消失，屬正常）

若檢索模式顯示「詞彙檢索（備援模式）」，代表 Secrets 裡的金鑰沒有被讀到，檢查 `GEMINI_API_KEY` 拼字。
