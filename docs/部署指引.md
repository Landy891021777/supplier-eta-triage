# 部署指引

兩件事：把專案推上 GitHub，以及（可選）部署成一個可公開點擊的網址。

**預估時間：GitHub 約 10 分鐘，雲端部署再約 5 分鐘。**

---

## 一、先確認 `.env` 沒有進版控

在做任何事之前，先確認這件事：

```bash
git status --short
```

**輸出裡不應該出現 `.env`。** 如果出現了，停下來檢查 `.gitignore`。
API 金鑰一旦推上 GitHub，就必須當作已外洩並立刻撤銷重發。

`.gitignore` 已經排除：`.env`、`data/*.csv`、`data/inbox/`、`output/`、
`__pycache__/`、以及面試準備筆記。

---

## 二、推上 GitHub

### 前置：設定 git 身分（只需做一次）

```bash
git config --global user.name "你的名字"
git config --global user.email "你的Email"
```

### 步驟 1：在 GitHub 上建立空的 repository

到 <https://github.com/new>：

- Repository name：`supplier-eta-triage`
- 選 **Public**（要讓面試官看得到）
- **不要**勾選 "Add a README file"、"Add .gitignore"、"Choose a license"
  —— 本專案已經有這些檔案，勾了會衝突

建完後 GitHub 會給你一個網址，像 `https://github.com/<你的帳號>/supplier-eta-triage.git`

### 步驟 2：推送

在專案資料夾裡執行（把網址換成你的）：

```bash
git remote add origin https://github.com/<你的帳號>/supplier-eta-triage.git
git branch -M main
git push -u origin main
```

第一次推送會要求驗證。三種方式，擇一：

| 方式 | 說明 |
|---|---|
| **瀏覽器登入**（最簡單） | 若已安裝 Git Credential Manager，會自動跳出瀏覽器視窗登入 |
| **Personal Access Token** | GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens，建一個有 `Contents: Read and write` 權限的 token，推送時「密碼」欄位貼這個 token（不是帳號密碼） |
| **GitHub Desktop** | 用圖形介面，選 Add Existing Repository 再 Publish |

### 步驟 3：確認

打開你的 repo 網頁，確認：

- README 有正常顯示（含表格與流程圖）
- **`.env` 不在檔案列表裡**
- commit 歷史有分階段，不是一個 "initial commit"

## 三、（可選）部署到 Streamlit Community Cloud

好處是履歷上可以直接貼一個能點的網址，並且命中職缺加分條件的「雲端平台部署」。

### 步驟

1. 到 <https://share.streamlit.io> 用 GitHub 帳號登入
2. 點 **New app** → 選你剛推上去的 repo
3. 設定：
   - Branch：`main`
   - Main file path：`app.py`
4. 點 **Deploy**，等 2–5 分鐘

### 重要：資料要能自動產生

`data/` 目錄被 `.gitignore` 排除了（因為它是可重新生成的產物），
所以雲端第一次啟動時會找不到資料。兩個解法：

**解法 A（建議）**：在 `app.py` 啟動時自動產生。
在 `main()` 的開頭加上：

```python
if not (ROOT / "data" / "po_master.csv").exists():
    import generate_data
    generate_data.main()
```

**解法 B**：把 `data/` 從 `.gitignore` 移除並提交進去。
簡單，但版控裡會塞入產物，不是好習慣。

### 設定金鑰（若要在雲端啟用 LLM）

**不要**把 `.env` 推上去。改用 Streamlit 的 Secrets 機制：

App 頁面 → 右下 **Manage app** → **Settings** → **Secrets**，貼上：

```toml
LLM_PROVIDER = "gemini"
GEMINI_API_KEY = "你的金鑰"
GEMINI_MODEL = "gemini-2.0-flash"
```

然後在 `src/llm/provider.py` 的 `_load_dotenv()` 之後補一段，
讓它也讀得到 Streamlit secrets：

```python
try:
    import streamlit as st
    for k, v in st.secrets.items():
        os.environ.setdefault(k, str(v))
except Exception:
    pass
```

### 公開部署的注意事項

- Community Cloud 的 app 預設**任何人都能看**。本專案用的是合成資料，
  所以沒有問題 —— 但如果之後換成任何真實資料，**不可以**部署在公開環境。
- 免費方案的 app 閒置一段時間會休眠，第一次開啟需要等它喚醒。
  面試前先開一次讓它醒著。

## 四、履歷上怎麼寫

建議在履歷的專案欄位放兩個連結：

```
供應商交期回覆解析與影響評估工具
GitHub: https://github.com/<帳號>/supplier-eta-triage
Demo:   https://<你的app>.streamlit.app
```

以及一句話說明。建議這樣寫（重點放在判斷，不是技術堆疊）：

> 以供應商端物料企劃的視角，將交期回覆信件自動解析、對位採購單，
> 並以十條可調權重的領域規則評估影響，把每日數十封回覆收斂為優先行動清單。
> 採規則層／LLM 分層解析並以對照實驗驗證分層必要性；
> 所有不確定的解析結果強制人工確認，不自動寫回系統。
