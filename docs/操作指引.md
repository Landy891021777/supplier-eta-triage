# 操作指引

給第一次使用這個工具的物料企劃同仁。**看完大約 5 分鐘，實際操作大約 3 分鐘。**

---

## 一、這個工具幫你做什麼

每天早上你會收到一批供應商的交期回覆信。這個工具幫你：

1. 把信讀完，抓出「哪一張採購單、新交期是哪天、對方到底有沒有承諾」
2. 依這家供應商過去「說定日期後實際還晚幾天」，推算一個比較保守的到料日
3. 加上料到廠後的收貨處理天數（進料檢驗、入庫、光阻回溫等），算出**可投產日**
4. 拿可投產日跟下游需求日比，算出**預估缺料天數**，排出今天該追的清單，
   每一筆都告訴你為什麼排這裡、建議你做什麼
5. 幫你把回信草稿打好
6. 讓你用平常講話的方式查採購單、料號、供應商

## 二、這個工具**不會**幫你做什麼

請先看這一段，比看功能重要。

- **不會自動寫回 ERP。** 所有交期都只是建議，要不要更新系統由你決定。
- **不會自動寄信。** 只產生草稿，寄不寄、怎麼改，你說了算。
- **不會替你判斷商務問題。** 該不該轉單、要不要跟供應商翻臉，工具不碰。
- **看不懂的時候會承認。** 標著 ⚠️ 的案件代表工具沒把握，請你自己看一眼原信。

## 三、三分鐘上手

### 步驟 1：打開工具

```bash
py -X utf8 -m streamlit run app.py
```

瀏覽器會自動開啟。若沒有，手動開 `http://localhost:8501`。

### 步驟 2：看最上面那排數字

```
收到信件 │ 自動濾除（確認無變更） │ 進入行動清單 │ 🔴 今天要處理 P1 │ ⚠️ 需人工確認
```

- **自動濾除**：供應商說「照原計畫、沒問題」的信，工具幫你濾掉了，不用看。
- **🔴 今天要處理**：這幾筆是今天不處理會出事的。先看這些。
- **⚠️ 需人工確認**：工具沒把握，需要你看一眼。

### 步驟 3：看「今日行動清單」

清單先依優先級排，同一級裡**缺料天數越多越前面**。

**預估缺料天數 = 保守到料日 + 收貨處理天數 − 下游需求日**

- 正數：預估會缺料，缺幾天
- 零或負數：還有緩衝（負幾天就是還有幾天）

優先級不是分數，是用下面的條件直接判斷的：

| 標記 | 條件 | 你該做的 |
|---|---|---|
| 🔴 P1 | 預估缺料，**而且**下游已排定（已排入投片／機台排程）或是瓶頸料 | 今天處理 |
| 🟠 P2 | 預估缺料但不屬 P1；或單一來源、緩衝只剩 3 天內；或供應商說會延卻沒給日期 | 本週要追 |
| 🟡 P3 | 其餘（有緩衝，或有已認證二源可轉單） | 留意即可 |
| ⚪ 待查 | 信裡的單號對不到系統，或讀不出新日期 | 請人工看原信 |

### 步驟 4：展開任一筆看理由與建議動作

點開任何一筆，你會看到：

- **為什麼是這個優先級** —— 例如「供應商說 10/09；這家供應商過去改期過的單有 80%
  在說定日期後 11 天內到，保守到料日 10/20；加上收貨處理 1 天，可投產日 10/21；
  比需求日晚 16 天」
- **建議動作** —— 只寫你自己能做的事：與採購確認能否向二源詢價、請品保確認替代料是否
  已通過驗證、通知生管確認排程、請 IQC 優先檢驗等。替代料在品保確認前**不會**被寫成可用
- **原始信件** —— 直接對照，不用另外去翻信箱
- **產生回信草稿** —— 按一下就有

### 步驟 5：需要的話，調整收貨處理天數

到「🛠 收貨處理天數」分頁。每個料號都有依料別的預設天數（例如光阻 2 天、光罩 3 天），
但實際情況你最清楚——這批要全檢、這家供應商改成減量檢驗，都會影響天數。

選料號、填天數、**填原因和姓名**，送出後行動清單會立刻重算。每次調整都有紀錄，
也可以恢復預設。

**這是工具內的設定，不會寫回 ERP 料號主檔。** 要正式改主檔，請照公司流程申請。

---

## 四、看到 ⚠️ 的時候該做什麼

⚠️ 代表以下三種情況之一：

| 情況 | 意思 | 建議動作 |
|---|---|---|
| 承諾強度不是「已確認」 | 供應商講得含糊，這個日期**不能拿去排產能** | 打電話或回信，逼一個確切日期 |
| 解析信心不足 | 工具看不太懂這封信 | 自己讀一次原信（可在展開處直接看到） |
| 有延遲但沒有日期 | 對方只說會延，沒說延到哪天 | 這是最該追的一種，務必要到日期 |

**這些案件的共同點：工具不會把它們的日期覆寫到系統。**
交期資料錯了，下游整條排程都會跟著錯，這個責任工具不會替你扛。

## 五、回信草稿怎麼用

按「產生回信草稿」後，工具會依案件情境擬一封信。草稿會：

- 明確寫出原承諾日、新交期、我方需求日
- 如果對方沒有明確承諾，**主動要求對方給出可承諾的確切日期**
- 如果緩衝不足，請對方評估部分提前交付的可能

**寄出前請務必自己讀過一遍。** 語氣、稱謂、跟這個窗口的關係，
只有你知道。工具只是幫你省下打字的時間。

## 六、物料智能檢索怎麼用

到「🔎 物料智能檢索」分頁，直接打字問，不需要記指令。例如：

| 想知道 | 可以這樣問 |
|---|---|
| 某張單的狀況 | 「PO-2026-04205 現在緊不緊急？」 |
| 某家供應商可不可靠 | 「SUP-R02 過去交貨準不準？」 |
| 某顆料有沒有備案 | 「PR-ArF-1088 有沒有第二家可以買？」 |
| 整體風險 | 「哪些料缺了沒辦法找別家救？」「快要趕不上生產的訂單有哪些？」 |
| 工具怎麼用 | 「畫面出現黃色驚嘆號該怎麼辦？」 |

**看回答時請注意三件事：**

1. **每句話後面的方括號是出處**，例如 `[PO:PO-2026-04205]`。
   下方「參考資料」可以展開看原始內容，有疑問就以原始內容為準。
2. **出現黃色警告**，代表回答引用了沒提供給它的資料，那句話可能是推測。
3. **回答「資料中沒有這項資訊」是正常的**。工具只根據系統資料回答，
   不會用常識補上 —— 例如供應商在系統裡是代號，問真實公司名稱會查不到。

問題裡帶上單號、料號或供應商代號，結果會最準確。

## 七、常見問題

**Q：畫面上寫「未偵測到 LLM 金鑰」，是壞掉了嗎？**
沒有。工具在沒有金鑰時仍可完整執行，只是遇到「純文字敘述型」的信
（例如「大概月底吧，我再跟你確認」）會解析失敗，並標記為需人工確認。
格式化的通知信不受影響。要接上金鑰請找 IT 或參考 `.env.example`。

**Q：清單上有一筆採購單號我沒看過，標成「待查」。**
代表信裡提到的單號在採購單主檔裡找不到。常見原因是供應商打錯字，
或那是別的單位的單。工具刻意不把它靜默丟掉 —— 這種案子通常有問題。

**Q：我調了收貨處理天數，明天打開會記得嗎？**
在公司內部環境會記得，設定存在工具自己的資料庫。公開的展示網址則會在閒置休眠或
重新部署後回到預設值。

**Q：為什麼沒有可以調的權重？**
舊版有十條規則各自加權，但那組權重是憑感覺訂的，說不出「25 分是怎麼來的」。
現在的排序是兩個日期相減，每一步都能在會議上驗算；你能調的是真正有實務意義的
參數（收貨處理天數），而不是一個抽象的分數。

**Q：可以匯出嗎？**
可以，清單下方有「⬇️ 匯出行動清單 CSV」。

**Q：我覺得某張單的分級根本是錯的。**
太好了，請直接告訴我哪一張、為什麼。**判斷被推翻是這個工具會變好的方式。**
分級的完整邏輯在 `src/triage.py`，每個條件都有寫為什麼這樣設計。

## 八、回饋

這個工具的第一版一定有不對的地方。最有價值的回饋是：

1. **哪一筆排錯了**（排太前面或太後面），以及你認為正確的順序
2. **哪個分級條件或預設天數不合實務**，以及你們實際上真正在看的是什麼
3. **哪封信解析錯了**，請附上信件編號

不需要客氣。工具是為了讓你少花時間，不是為了證明它很聰明。
